# 项目战略计划

## 使命

建立一套可信、可复现且口径一致的 AMD GPU ANS 性能评估体系，解释当前
HIP-ANS 解码器与论文中 NVIDIA 实现之间的带宽利用率差距，并为下一阶段的
优化投入提供可验证的决策依据。

本计划只描述战略目标和成功标准。实际进展、技术证据、阻塞和近期动作记录在
[STATUS.md](STATUS.md) 中。

## 战略任务

### P0：建立可信的现状认知

明确已有能力、历史结果、测量口径和外部依赖，形成后续工作共同采用的事实基础。

成功标准：现有资产、有效结果、已知局限和可复用能力均有清晰记录，且不会把历史
探索结果误当作标准化结论。

### P1：形成标准化性能基线

建立统一、可复现的测量入口和指标口径，并获得同一平台上的可实现内存带宽基准，
使不同实验和外部研究结果能够在明确边界下比较。

成功标准：正确性、性能、数据规模和环境来源均可验证；核心利用率指标只有一种
权威定义；基线结果可以被独立重复。

依赖：P0。

### P2：收集架构级瓶颈证据

从内存、计算、并行度、同步、跨芯粒访问和流水线行为等维度收集足够证据，区分
表象吞吐率与真实硬件瓶颈。

成功标准：关键瓶颈维度均有实测证据，无法获得的证据被明确标记，结论不依赖单一
指标或未经验证的推断。

依赖：P1。

### P3：完成性能差距归因

量化各类限制因素及其可改善空间，判断性能差距主要来自架构适配、部署与调度、
数据移动和流水线设计，还是 ANS 解码本身的根本限制。

成功标准：每项主要判断都有证据、估算范围和置信边界，并能形成明确的主次排序。

依赖：P1、P2。

### P4：建立与论文的一致性对照

在不混淆独立解码、融合计算和端到端性能的前提下，对照论文的评估对象、模型和
指标，明确哪些结果可以直接比较，哪些只能作为背景参考。

成功标准：论文数据来源、比较口径、缺失输入和不可比因素全部显式呈现，不以合成
数据替代缺失的真实模型数据。

依赖：P1；最终解释依赖 P3。

### P5：形成下一阶段决策路线

依据瓶颈归因，提出按收益、风险和依赖排序的后续方向，为下一阶段是否投入架构适配、
调度改进、内存行为优化或流水线融合提供依据。

成功标准：建议与证据一一对应，能够区分近期可验证改进和长期研究方向，并避免在
证据不足时承诺具体收益。

依赖：P3、P4。

## 战略边界

- 当前阶段以测量、证据收集和归因为核心，不优化或改变编解码算法。
- 上游 hipANS 保持只读，实验不得污染其源码状态。
- 论文中的融合解码与计算结果，不直接等同于独立解码器的全局内存输出吞吐率。
- 缺失的硬件计数器、权限或模型数据必须被记录，不得用推测结果填补。
