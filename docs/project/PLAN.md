# 项目战略计划

## 使命

在 AMD GPU 上实现真实压缩权重推理场景的性能优化：当前覆盖 MI300X 与 MI350X，模型权重提前完成 ANS
压缩，推理时按计算需要解码并直接供矩阵计算消费。论文提供场景参考；重现论文
数字或对齐全部评估模型不再是项目的主任务。

任务分为两个主要阶段：第一阶段实现并优化解码到片上存储；第二阶段将解码与
矩阵计算融合并建立流水线。准备工作和最终工作负载验证分别记录为 S0、S3。
实际进展与工程证据见 [STATUS.md](STATUS.md)，使用相同编号。

## 战略任务

### S0：确立真实场景与工作负载

选择具有真实模型来源的代表性权重和计算场景，明确数值格式、正确性要求及
性能目标，使后续实验回答实际推理中的问题。

已有与上游 entropyflow-lab 对应的原生 FP8 专家矩阵，用于验证工程路径。
本轮优先原生 FP8，排除 4-bit；BF16 为后续格式对照。代表性测量场景由 S1/R0
具体确认。

成功标准：输入来源、数值语义、场景边界和验收指标清晰可查；可从代表性层启动
工作，不以完整论文模型集合为先决条件。

### S1：实现并优化片上解码（第一阶段）

在预压缩权重已经准备好的条件下，构建按计算粒度解码到片上存储的路径，分析
性能限制，并通过实验获得可验证的改进。真实场景 baseline 与优化均属于本阶段。

S1 baseline 必须使用当前未优化 hipANS 的实际编解码实现，并在所选真实计算
场景的权重需求下建立 LDS 解码基线。资源供给诊断可以辅助解释结果，但不以
replicas 饱和吞吐作为主要验收标准，也不以它替代真实推理负载。
此前错误 scalar baseline 已撤销；实际 hipANS 的已有测量作为工程诊断保留。

S1 按以下交付顺序推进，详细范围见
[S1 真实场景交付计划](DELIVERY_REAL_SCENARIO_BASELINE.md)：

| 子阶段 | 目标 | 交付结果 |
|---|---|---|
| R0 | 确认真实权重与推理计算场景 | 经核实并确认的代表性矩阵、格式、推理阶段及权重消费需求 |
| R1 | 建立场景对应的离线 artifact 和 LDS 正确性验证 | 权重可复用，目标 tile 可逐位恢复，开销边界清楚 |
| R2 | 建立 MI350X / MI300X 场景 baseline | 当前未优化 hipANS 的可重复性能结果及场景限定 |
| R3 | 对场景 baseline 做硬件证据归因 | 瓶颈证据、限制和下一项优化方向 |

阶段验收：R0–R3 均有可复查证据；解码阶段代理结果与后续融合 GEMM 结果
边界明确。算法优化按独立、受控的子任务逐项验证；MI350X 优先，MI300X 单独
测量和解释。

成功标准：真实权重可以正确恢复；性能指标覆盖数据供给和解码产出；优化效果
有重复测量与硬件证据；能够明确指出进入融合阶段时剩余的瓶颈。

依赖：S0。

### S2：实现解码与矩阵计算融合（第二阶段）

让矩阵计算直接消费片上解码结果，通过流水线组织重叠解码和计算，并以实际
层延迟和吞吐验证收益。

成功标准：数值结果符合所选格式的正确性要求；与相同输入和计算条件的基线
相比，收益及适用范围有明确证据；能够解释不同推理负载下的性能变化。

依赖：S1。

### S3：验证部署价值并扩展目标格式

在代表性推理负载下验证优化的适用范围，逐步覆盖项目需要的低比特权重以及
不同模型架构，为部署和下一阶段投入提供依据。

成功标准：结论覆盖性能、正确性和适用条件；低比特格式及模型扩展依据实际
需求推进，不把单一微基准的收益直接等同于完整服务收益。

依赖：S2；必要的工作负载选择可提前在 S0 中准备。

## 战略边界

- 当前允许为上述目标修改并优化 hipANS 的解码及融合计算路径；本仓库负责
  工作负载、测量、验证、profiling 与实验记录。
- 保留已有标准接口和历史结果作为可复查的工程资产。
- hipANS 源码可修改，两仓库分别记录改动和提交；构建产物继续放在本仓库。
  entropyflow-lab 及其现有数据/cache 继续只读。
- 离线压缩的正确性、推理时的性能、模型数值格式的转换分别有明确记录。
- 完整论文复现转为可选参考工作，不阻塞当前两阶段优化。
- 工作负载规模、权重复用及访问顺序由目标推理计算决定，不为突破缓存容量或
  获得更高吞吐而人为扩展；解码阶段代理实验不等同于融合 GEMM 或完整推理。
