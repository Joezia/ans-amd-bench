# 重做 S1 baseline：当前 hipANS 的充分供给吞吐

2026-10-11，取代此前 scalar reference 作为 S1 baseline 的验收资格。
对应战略 S1。保留真实 FP8 输入来源；错误 baseline 由新结果覆盖，不保留为对照。

## 目标与范围

回答：当前未优化 hipANS 在工作量足够、计算资源充分供给的条件下，解码到 LDS
的有效吞吐最多达到多少。这里的“最多”是规定部署搜索范围内、经重复确认的
实测最大值，不是数学证明的算法上限。

本轮不改解码算法、符号格式、概率精度或每流解码规则；只进行必要的 LDS 输出
适配、正确性验证与资源供给实验。未开始 codec 优化、GEMM 融合或 4-bit 扩展。

## 交付节点

| 编号 | 任务 | 成功标准 |
|---|---|---|
| H0 | 固定当前 hipANS 与真实输入 | 实际运行实现和来源可追溯，不使用替代 codec |
| H1 | 建立 hipANS 原生离线包与 LDS 路径 | 当前 hipANS 编码结果可从实际 LDS 正确读回，计时中保留有效 LDS 写入 |
| H2 | 测量充分供给下的吞吐 | 工作量扩展、部署与并发比较有统一口径，并验证吞吐是否趋于稳定 |
| H3 | 确认并解释实测最大值 | 独立重复测量、资源与等待证据齐全，明确搜索边界和场景局限 |

## 场景边界

沿用上游对应的真实 DeepSeek-V4-Flash-Base FP8 矩阵，不重新量化。
资源饱和实验可在独立地址放置同一权重的多个副本；必须分别记录唯一模型数据、
物理工作集和实际生产量，不把副本解释成更多模型参数或真实大层。
以共同完成时间计算并发总吞吐，不相加独立队列的局部速率。

仅有代码或排队任务不算完成。实测结果落盘并验收后，才进入后续优化。
工程步骤、实际 job 与结果证据见 STATUS 与专门使用说明。
